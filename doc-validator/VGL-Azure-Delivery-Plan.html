01 Executive summary

A working POC, ready to become a supported product

The proof-of-concept already validates loadsheets and documents end to end: deterministic quality checks (searchable text, OCR, blank pages, orientation, alignment, document-number legibility) and an AI layer on Azure OpenAI GPT-4o that reads the rendered pages to compare loadsheet data — or, when no loadsheet is supplied, to extract the document number, title, revision, issue date and purpose, contract/PO number, author, producer and security classification.

This proposal covers what it takes to run that reliably for the business: hosting it on Azure, adding email and Microsoft Teams notifications, processing documents at volume, and securing and monitoring the platform — plus a transparent cost model so every validated document has a known price.

03 Email & Teams notifications

Results delivered where the team already works

Email — Azure Communication Services

On completion, the validator emails the HTML report (and a JSON attachment) to the submitter and document-control mailbox. Pay-as-you-go: $0.00025 per email plus $0.00012 per MB list price. A report with embedded evidence images runs ~1–3 MB, so ~$0.0005–$0.0009 per notification — effectively negligible against the AI cost.

Microsoft Teams

A pass/fail card is posted to a document-control Teams channel with the verdict, headline reasons and a link to the full report. Delivered via a Teams webhook / Microsoft Graph — no per-message charge on standard Microsoft 365 licensing. A future two-way bot (submit & query from Teams) is a scoped add-on.

04 Per-document running cost

What each validated document actually costs

The dominant variable cost is Azure OpenAI GPT-4o, billed on tokens: $2.50 per 1M input tokens and $10.00 per 1M output tokens list price. Rendered pages are charged as image tokens (~1,100 tokens for a high-detail A4 page, plus its extracted text). The figures below are measured from actual runs on VGL documents.

Why cost does not simply track page count

The engine sends the first three pages, the last page, and title-block crops — the places identifiers live — not every page. So a 32-page document and a 3-page document cost far less than 10× apart. Cost scales with pages actually read and image density, not raw length. Full-every-page coverage is available as a lever where drawings demand it (see the third row).

Optional OCR upgrade

Tesseract OCR is free and runs in-container. Where scan quality is poor, Azure Document Intelligence (Read) gives higher accuracy at $1.50 per 1,000 pages = $0.0015/page list price — added only for documents that need it.

Scale lever — Provisioned Throughput

Above ~150–200M tokens/month (≈ 10k+ standard docs/month with full processing), Azure OpenAI Provisioned Throughput Units (PTU) — from ~$2,448/unit/month list price — can cut AI cost by up to ~70% versus pay-as-you-go and give predictable latency. We size this during discovery once real volume is known.

09 Assumptions, risks & exclusions

What these numbers rest on

Assumptions

  • Client provides the Azure subscription, Entra tenant, network landing zone and representative documents.
  • GPT-4o Standard (pay-as-you-go); PTU evaluated once real volume is known.
  • Existing deterministic checks, OCR and report format are reused — no new ML model training.
  • Token counts derived from sample VGL documents; real mix will vary.

Excluded (scoped separately)

  • Deep SharePoint / SDx system integration beyond agreed interfaces.
  • Formal penetration testing & security accreditation.
  • 24×7 operations (covered by the AMS option).
  • Historical data migration and bulk back-processing.
Pricing validity

All Azure figures are public list prices as of July 2026, in USD, and vary by region and Microsoft agreement. They are planning estimates, not a quotation — confirm in the Azure Pricing Calculator and against your enterprise agreement before commitment.

10 Recommended next step

A short, paid discovery to lock scope and price

We recommend a 2–3 week discovery (workstream 1) to confirm requirements, size real document volume, choose Container Apps vs App Service and Standard vs PTU, and validate accuracy on a broader document sample. It converts this planning estimate into a firm, fixed-price statement of work — and is credited against the build if you proceed.
